1.该模板工程用于快速搭建stm32f103c8t6的HAL + FREERTOS实验环境
2.具体keil HAL工程配置参考链接：https://zhuanlan.zhihu.com/p/671352453
3.具体keil FREERTOS工程配置参考链接：https://zhuanlan.zhihu.com/p/15647351678
3.该模板的意义在于脱离cubemx，仅使用hal库+ MDK keil + FREERTOS源码快速搭建实验工程。
4.实验代码如下：OLED打印“hello,2026!”
5.硬件环境：stlink v2
6.FreeRTOS手动移植中遇到的问题：
    (1)keil使用freertos出现error: unknown type name ‘__forceinline’ note: expanded from macro‘portFORCE_INLINE
        1.使用cubemx固件库中的文件进行替换，STM32F103 cubemx固件库FreeRTOS兼容层开源代码地址：https://github.com/STMicroelectronics/stm32-mw-freertos/tree/cdc07b553ee9a9676988e5089a1d484da5d37c9c
        2.更换教程：https://blog.csdn.net/2301_80165137/article/details/145326988
    (2)freeRTOS和HAL库时钟冲突问题
        1.解决方案：一般不会删掉SysTick_Handler()这个中断函数，而是把xPortSysTickHandler();和HAL_IncTick();都一起放在SysTick_Handler()中
        2.教程：https://www.firebbs.cn/forum.php?mod=viewthread&tid=30367
        3.本模板的解决方案为：
            (1)将xPortSysTickHandler的声明移动到FreeRTOS_config.h文件中，从而进行对外暴露。
            (2)stm32f1xx_it.c中的SysTick_Handler做如下修改
                void SysTick_Handler(void)
                {
                    HAL_IncTick();
	                #ifdef FREE_RTOS_EN
	                xPortSysTickHandler();
	                #endif
                }
            (3)通过bsp_config.h中启用宏开关来启动xPortSysTickHandler。此外，这种方案在单独启用HAL时，SysTick配置由HAL_Init负责，当同时启用了FreeRTOS后，则SysTick配置会被FreeRTOS覆盖。但实际这符合用户使用习惯。
